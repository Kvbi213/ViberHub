# VibeHub Release v0.1.7 — 2026-10-20
> Status: PRODUKCJA | Środowisko: Local-First Observability & Multi-Agent Bridge + MCP Server

## Główne zmiany (Changelog)
- `[+]` **Wdrożenie dedykowanego serwera MCP (Model Context Protocol)**:
  - Protokół: JSON-RPC 2.0 stdio w `apps/bridge/src/mcp/server.ts`.
  - Dostępne narzędzia:
    - `vibehub_push_status`: bezpośrednie raportowanie stanu, aktywnego promptu i narzędzia do klastra.
    - `vibehub_checkpoint`: rejestracja kamieni milowych architektury i zmienionych plików.
    - `vibehub_get_status`: odczyt telemetrii klastra i stacji roboczych.
  - Komendy CLI:
    - `vibehub mcp`: uruchomienie serwera na standardowym wejściu/wyjściu.
    - `vibehub setup-mcp`: 1-klikowa konfiguracja i rejestracja w `~/.gemini/antigravity/mcp.json`.
- `[+]` **Optymalizacja telemetrii i eliminacja anomalii statusów w `antigravity-observer.ts`**:
  - Wsteczne skanowanie logu `transcript.jsonl` przy inicjalizacji z natychmiastowym odzyskiem prompta użytkownika.
  - Dynamiczny status `WORKING` (zielony pulsujący badge) przy aktywności w ostatnich 4 minutach oraz podczas wywołań narzędzi.
  - Eliminacja sesji zombie i automatyczne czyszczenie sesji nieaktywnych przez ponad 20 minut z Firestore.
- `[+]` **Naprawa uprawnień Firestore Security Rules dla `/settings`**:
  - Dodano jawną regułę dla `rooms/{roomId}/devices/{deviceId}` oraz `match /{document=**}`.
  - Stacje robocze natychmiast rejestrują się w klastrze po uruchomieniu Bridge.
- `[+]` **Wdrożenie produkcyjne**:
  - Firebase Firestore Rules zaktualizowane na projekcie `viberhub-8842f`.
  - Frontend wyeksportowany i wdrożony na Firebase Hosting (`https://viberhub-8842f.web.app`).
  - Przebudowany i zlinkowany globalnie pakiet `@vibehub/bridge` (`vibehub`).
